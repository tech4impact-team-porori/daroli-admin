# 문구 가이드 — 다로리 관리자 대시보드

> 목적: 화면 문구에서 "AI가 써준 티"를 없앤다.
> 이 문서는 `lib/status.ts`(상태 라벨)와 짝을 이룬다. 라벨은 거기, 문장 규칙은 여기.

---

## 0. 한 줄 요약

**문장을 써도 되는 자리와 쓰면 안 되는 자리가 따로 있다.**

| 자리 | 문장 | 이유 |
|---|---|---|
| 확인 다이얼로그 | ⭕ | 시스템이 사용자 행동에 응답하는 순간 |
| 에러 메시지 | ⭕ | 위와 동일 |
| 폼 검증 메시지 | ⭕ | 위와 동일 |
| 빈 상태(empty state) | ⭕ 단문 1개 | 위와 동일 |
| **상태 배지** | ❌ | 사용자가 훑는 자리 |
| **액션 큐 detail** | ❌ | 위와 동일 |
| **테이블 셀** | ❌ | 위와 동일 |
| **통계 서브텍스트** | ❌ | 위와 동일 |
| **차트 캡션** | ❌ | 차트가 스스로 말해야 함 |

훑는 자리에 종결어미(`~습니다`, `~합니다`)가 등장하면 그건 신호다.

---

## 1. 훑는 자리의 3원칙

### 원칙 1 — 명사로 끝낸다

```
❌ 승인됐지만 아직 매니저에게 안 나갔습니다
⭕ 지급 대기 1,240,000원
```

### 원칙 2 — 접속사가 보이면 문장이 된 것

`~지만` `~하고` `아직` `현재` `~때문에` 가 들어가면 두 가지를 한 칸에 우겨넣은 상태다.
정보를 계층으로 쪼갠다: **배지 = 지금 상태 / 서브텍스트 = 숫자·날짜 / 툴팁 = 설명**

### 원칙 3 — 새 사실이 없으면 비운다

가장 흔한 AI 냄새는 **라벨을 다시 설명하는 detail**이다.

```
❌ label: "배정 예산 미설정"  detail: "이번 달 배정 예산이 설정되지 않았습니다"
⭕ label: "배정 예산 미설정"  detail: "2026-08"

❌ label: "매니저 심사 대기"  detail: "다음 단계 진행이 필요합니다"   ← 정보량 0
⭕ label: "매니저 심사 대기"  detail: "2명 · 신청 1 · 교육이수 1"
```

detail에 넣을 새 사실이 없으면 **문장으로 채우지 말고 빈칸으로 둔다.**

---

## 2. 액션 큐 detail 포맷 (고정)

```
{숫자+단위} · {판단에 필요한 분해값 또는 경과 기간}
```

관리자가 위에서 아래로 스캔할 때 형식이 하나면 읽는 속도가 붙는다. 지금은 8개 항목의 문장 구조가 제각각이라 매번 다시 읽어야 한다.

| key | label | detail |
|---|---|---|
| approved-unpaid | 정산 필요 | `1,240,000원 · 매니저 6명분` |
| requested-payout | 출금 신청 대기 | `3건 · 최장 5일 경과` |
| pending-log | 일지 검토 대기 | `12건 · 최장 8일 경과` |
| stale-request | 배정 지연 요청 | `2건 · 24시간 초과` |
| pending-manager | 매니저 심사 대기 | `2명 · 신청 1 · 교육이수 1` |
| unassigned-recipient | 미배정 대상자 | `4명 · 화양읍 3 · 금천면 1` |
| shortage-region | 매니저 부족 지역 | `2곳 · 운문면, 각북면` |
| budget-setup | 배정 예산 미설정 | `2026-08` |

> 일부는 `ActionQueue` 타입 확장이 필요하다(매니저 명수, 출금 최장 경과일, 미배정 대상자 읍·면 분해). 전부 기존 데이터에서 계산 가능하며 판정은 `lib/calc.ts`에만 둔다.

---

## 3. 어미 통일

에러 메시지는 **`~하지 못했습니다`** 하나로 통일한다.

```
⭕ 매니저 목록을 불러오지 못했습니다
⭕ 설정을 저장하지 못했습니다
❌ 승인 처리 중 오류가 발생했습니다   → 승인하지 못했습니다
❌ 반려 처리 중 오류가 발생했습니다   → 반려하지 못했습니다
```

"오류가 발생했습니다"는 관공서 시스템 말투다. 무슨 일이 있었는지 말해주지 않는다.

## 4. 상태 라벨 종결 일관성

같은 계열 상태끼리 어미 길이를 맞춘다.

| 도메인 | 현재 | 문제 |
|---|---|---|
| 일지 | 검토 대기 / 승인 / 반려 | `승인`만 2글자 |
| 출금 | 신청 중 / 지급 완료 / 반려 | `지급 완료`만 완료형 |
| 정산 | 산정 / 승인 | 둘 다 짧음 |

→ 완료 상태는 전부 `완료`로 끝내는 쪽을 권장: `승인 완료` / `지급 완료` / `산정 완료`.
단 **`lib/status.ts` 라벨은 기획서 원문 표기**이므로, 바꾸려면 기획 담당자 확인이 먼저다.

## 5. 개별 지적

### `app/page.tsx:330` — 차트 캡션

```
❌ 제출과 승인의 간격이 벌어질수록 검토가 밀리고 있다는 신호입니다.
```

차트 밑에서 해석을 대신 해주는 문장 = 전형적인 AI 패턴.
지우거나, 실제 수치로 바꾼다 → `미승인 12건 (제출 34 / 승인 22)`

### `app/requests/page.tsx:144` — 배지 설명 배너

```
❌ 배정 지연 배지가 붙은 건은 접수된 지 24시간이 지나도록 시간 제안이 없습니다.
```

배지 정의를 상시 배너로 띄우면 매번 읽고 넘겨야 한다. **배지 자체의 툴팁**으로 옮긴다.

### `app/recipients/page.tsx:394` — 마스킹 버튼

```
❌ ●●●● 보기
⭕ 주소 보기   (또는 눈 아이콘)
```

마스킹 문자를 버튼 라벨로 쓰면 무엇을 여는 건지 알 수 없다.

### `components/layout/topbar.tsx:7` — 기간 선택

```
❌ 기간: 이번 달 ▾
```

`▾`를 텍스트로 넣었고, 대시보드에 월 Select가 따로 있어 기능이 중복된다.
실제로 동작하지 않는다면 제거한다.

### `app/settings/page.tsx:156` — 단가 변경 확인

지금 3문장. **이건 파괴적 작업이라 문장이 맞다.** 다만 2문장으로 줄일 수 있다.

```
⭕ 단가가 20,000원 → 22,000원으로 바뀝니다.
   아직 승인되지 않은 정산만 새 단가로 다시 계산되고, 승인된 정산은 그대로 유지됩니다.
```

---

## 6. 잘 되어 있는 것 (유지)

- 사이드바 메뉴 — 전부 2~5자 명사구
- 테이블 헤더 — 종결어미 없음, 단위 일관
- 빈 상태 — `표시할 매니저가 없습니다` 형태로 통일됨
- 확인 다이얼로그 — 대상·금액·결과를 명시함
- 지역 지도 툴팁 — 숫자 중심, 설명 없음
