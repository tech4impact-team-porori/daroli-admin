### 🔴 막힌 것 — 운영 투입 전 반드시 해결

**① 원격 저장소가 없습니다.**
`git remote -v` 가 비어 있습니다. **코드가 승환님 노트북에만 존재합니다.** 노트북이 고장나면 작업이 사라지고, 백엔드 담당자가 연결 작업을 도울 방법도 없습니다. 브랜치 이름도 아직 `feature/login-api` 이고 `main` 이 없습니다.

**② 인증이 전혀 없습니다.**
`middleware.ts` 없음, `/login` 라우트 없음. 기획서 P0 1번 항목입니다.
지금은 가짜 데이터라 괜찮지만, **실데이터를 붙인 채로 배포하면 URL 아는 사람 누구나 어르신 상세 주소·건강 상태·아동 실명을 봅니다.**

**③ 상단바 두 버튼이 Phase 1 껍데기 그대로입니다.**
"기간 필터"와 "개인정보 보호 모드"가 아무 동작도 하지 않습니다. 마스킹은 `/recipients` 안에만 있고, **`/review` 에는 마스킹이 하나도 없습니다.**

### 🟡 알아둘 것

- 프로젝트가 **OneDrive 동기화 폴더 안**에 있습니다. `node_modules` 가 계속 동기화되면서 느려지고 충돌 위험이 있습니다
- `CLAUDE.md` 의 "현재 상태" 문구가 아직 "Phase 0 완료"입니다

## 2. 순서의 원칙

```
지금(가짜 데이터)          →  배포해도 안전. 공개 URL 괜찮음
     ↓
프론트 마무리 (12·13·14)   →  실데이터를 감당할 준비
     ↓
인증 (18)                  →  로그인한 관리자만
     ↓
실데이터 연결              →  이 순서가 뒤바뀌면 개인정보 유출
```

**두 가지만 지키면 됩니다.**

1. **Phase 12(마스킹)는 Phase 16(DB 연결) 전에 반드시 끝난다.** DB를 붙인 뒤에 마스킹을 만들면, 실제 어르신 정보가 화면에 뜬 채로 작업하게 됩니다
2. **Phase 18(인증) 전에는 실데이터를 어디에도 배포하지 않는다**

Phase 12·13·14는 서로 의존하지 않으므로 **순서를 바꿔도 됩니다.** 다만 셋 다 16 전에 끝나야 합니다.

**목표:** 코드가 노트북 밖에 존재하게 만든다.

```bash
git branch -m feature/login-api main

git remote add origin https://github.com/<계정>/daroli-admin.git
```

**완료 기준:** 다른 컴퓨터에서 클론 → 설치 → 실행이 된다.

### ▶ Phase 12 — 개인정보 마스킹 전역화

**목표:** DB 붙기 **전에** 개인정보 보호 장치를 완성한다.

**① 마스킹을 전역 Context로** — 지금은 `/recipients` 안에만 있음
- 상단바 토글에 연결. **기본값 ON**. 현재 상태 배지 표시

**`/review` 에 마스킹이 하나도 없습니다.** 일지 카드에 이게 다 뜹니다:

| 항목 | 코드 | 성격 | 마스킹 |
|---|---|---|---|
| 대상자 실명 | `log.recipientName` | 아동 포함 | `김○○` |
| 활동 장소 | `log.place` | 대상자 주소 자동 채움 | 읍·면까지만 |
| 특이사항 | `log.note` | **건강 상태 변화 기재 = 민감정보** | `●●●●` + [보기] |
| GPS 좌표 | `gpsStart.lat/lng` | 소수점 4자리 ≈ **11m. 집 위치 특정 가능** | 거리만 표시, 좌표는 [보기] |
| 첨부 사진 | `log.photos` | 초상권 | 블러 + [보기] |

**② 상단바 "기간 필터"는 만들지 말고 제거**

전역 기간 필터는 기획서 원문에 없고 제가 제안(🟨)했던 것인데, 기간이 필요한 화면 3개가 이미 각자 필터를 갖고 있습니다.

| 화면 | 기존 필터 | 근거 |
|---|---|---|
| `/` 대시보드 | `selectedMonth` | |
| `/review` | `monthFilter` | 🟦 기획서 B-3 "필터: 월, 상태, 매니저" |
| `/payments` | `selectedMonth` | 🟦 기획서 B-6 "월 선택" |
| `/requests` | 없음 | 🟦 기획서 B-2에 기간 필터 없음 |

전역 필터를 붙이면 같은 화면에 월 선택이 두 개가 됩니다. **상단바에서 버튼을 지웁니다.**

**완료 기준:** 상단바 토글을 끄면 `/recipients` 와 `/review` 양쪽에서 동시에 마스킹이 풀린다.

### ▶ Phase 13 — 대시보드 재설계 (액션 중심) ★ 신규

**목표:** 대시보드를 "현황판"에서 "오늘 할 일 목록"으로 바꾼다.

**근거 문서: `docs/대시보드_재설계.md`** — 명세 전체가 여기 있습니다. 특히 2장(누락 추적표)과 4장(액션 큐 8종).
와이어프레임 비교(A안 3탭 vs B안 액션 중심) 결과 **B안 채택 확정**.

**할 일**
1. `lib/types.ts` — `ActionQueue` 인터페이스 추가, `DashboardData` 에 `actions` 필드
2. `lib/calc.ts` — 액션 큐 판정 함수. 화면에서 계산하지 않는다
   - `oldestPendingDays`, `staleRequestCount`, `pendingManagerCount`,
     `unassignedRecipientCount`, `shortageRegions`
   - `staleRequestCount` 는 `/requests` 의 `STALE_HOURS = 24` 상수를 **공유**할 것
3. `lib/data/mock.ts` — `getDashboard()` 가 `actions` 를 채우도록
4. `app/page.tsx` 전면 교체 — Tabs 제거, 3섹션 구조
5. `lib/calc.test.ts` — 경계 테스트 (pending 0건일 때, 정확히 24시간일 때)

**새 구조**
```
① 지금 처리할 일    화면의 60%. 8종 중 해당되는 것만. 0건이면 줄 자체를 안 그림
② 이번 달 현황      통계 타일 4개. 액션 없음
③ 활동 추이         6개월 차트, 높이 100px 내외
```

**액션 큐 정렬 원칙: 사람이 기다리는 것 > 일이 밀리는 것 > 준비가 안 된 것**

**완료 기준:** 화면을 열고 3초 안에 "오늘 뭘 해야 하는지" 알 수 있다. 전부 0건이면 `지금 처리할 일이 없습니다` 한 줄만 보인다.

**⚠️ 이건 기획서 Ver 1.0 B-1(🟦 확정)의 변경입니다.** Phase 15에서 팀에 명시적으로 알립니다.

### ▶ Phase 17 — DB 연결 ① 읽기

**목표:** 화면에 진짜 데이터가 뜬다. 단, **아직 아무것도 바꾸지 않는다.**

- `lib/data/real.ts` 생성 — `DataSource` 인터페이스 구현
- 환경변수 전환: `NEXT_PUBLIC_USE_REAL_DB=true`
- **조회 함수부터만.** 쓰기 함수는 아직 mock 유지
- 백엔드 응답이 우리 타입과 다르면 **`real.ts` 안에서만 변환.** 화면 코드는 손대지 않음

**검증 — 이 Phase의 핵심**
백엔드에 mock과 같은 데이터를 넣고 **양쪽 화면 숫자를 대조**합니다. 특히 예산 4단계와 매니저별 잔액. 다르면 계산 기준이 어긋난 겁니다.

### ▶ Phase 18 — DB 연결 ② 쓰기 + 서버 가드 검증

**목표:** 승인·정산·지급이 실제로 저장된다.

개발자 도구로 직접 요청을 보내서 서버가 막는지 확인합니다.

| 시도 | 기대 결과 |
|---|---|

| 관리자 아닌 계정으로 승인 요청 | 서버가 거부 |

**하나라도 뚫리면 백엔드 담당자에게 돌려보냅니다.** 협상 대상이 아닙니다 — 공적 재원이고 감사 대상입니다.

**목표:** 실제로 쓰이기 시작하고, 승환님이 손을 떼도 굴러간다.

**운영 배포**
- **운영 환경을 미리보기와 분리** — 별도 배포 + 별도 DB (Phase 11 URL은 계속 가짜 데이터)
- 환경변수 분리, DB 백업 설정

**한 달 파일럿**
- 매니저 6명, 실제 일지로 한 달 정산을 끝까지 돌려본다
- **기존 엑셀과 병행해서 숫자를 대조.** 이걸 안 하면 첫 달 정산에서 사고가 납니다
- 담당자 교육 + 사용 설명서 (1~2쪽)

**인수인계**
- 학기 종료 후 유지보수 주체 확정
- 저장소 소유권 이전, 운영 문서(배포 방법·환경변수·연락처)
- 남은 미해결 이슈 인계

**완료 기준:** 한 달치 정산이 엑셀 없이 이 화면만으로 끝난다.
